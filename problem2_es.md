Problema:
Todos los endpoints de la People API (`GET /api/people`, `GET /api/people/{id}` y `GET /api/people/page`) son de acceso público. Cualquier cliente que alcance el servidor puede leer la lista completa de personas, incluyendo datos personales como email y fecha de nacimiento, sin identificarse. Pedido: Como medida inicial de seguridad, exigir un header `X-API-Key` en cada request a la API. Los requests sin el header deben rechazarse con `401 Unauthorized`, y los que traigan una clave inválida con `403 Forbidden`, ambos usando el mismo formato problem-detail que las respuestas de error existentes. La clave esperada debe leerse de la configuración (una variable de entorno), nunca hardcodeada, y la comparación debe hacerse en tiempo constante. Es una API demo, por lo que una única clave compartida es aceptable por ahora; mecanismos más fuertes (roles, JWT) se irán agregando de forma incremental.
