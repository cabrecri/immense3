Problem:
All endpoints of the People API (`GET /api/people`, `GET /api/people/{id}` and `GET /api/people/page`) are publicly accessible. Any client that can reach the server can read the full list of people, including personal data such as email and birth date, without identifying itself. Request: As an initial security measure, require an `X-API-Key` header on every request to the API. Requests without the header must be rejected with `401 Unauthorized`, and requests with an invalid key must be rejected with `403 Forbidden`, both using the same problem-detail format as the existing error responses. The expected key must be read from configuration (an environment variable), never hardcoded, and the comparison must be done in constant time. This is a demo API, so a single shared key is acceptable for now; stronger mechanisms (roles, JWT) will be added incrementally.
